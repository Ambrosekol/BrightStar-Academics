What Brightstars Academics is

Brightstars Academics is a school platform that runs as one deployment serving many schools. A school gets a portal of its own: its own web address, its own PostgreSQL database and its own folder of files. Inside it the school runs entrance examinations, day-to-day administration (classes, subjects, assignments, tests, results, report cards, promotion), student and parent self-service, finance and receipting, a library, and role-based staff governance. No school can see, reach or affect another's data.

It began as a single-school application and was turned into a platform. That history explains a few names you will meet in the code; it never explains a design choice you should copy. If you find something school-specific in the code, treat it as a bug and tell someone.

Two ideas shape everything. A school gets a portal, not a website: a school's address serves sign-in and the staff, student, parent and candidate areas, nothing else. And the platform issues the address: creating a school immediately gives it <code>.<portal domain>; a school that wants its own domain adds a CNAME record pointing at it.

Who these pages are for

Everyone who has to understand, run or change the platform, from a first-week hire to the person deciding how to deploy it. The pages are written so that a beginner can read them in order, and an experienced developer can jump straight to what they need. Each page says what a part does, why it is built that way, and where in the code to look. Anything that looks like core/security.py is a link to that file's entry in the module reference.

How these pages are made

Two kinds of page. The hand-written pages explain and advise. The Reference pages (modules, routes, data model, permissions, templates) are generated from the code every time the server starts, by {{ file('control_plane/docsgen.py') }}, so they cannot fall behind it. A contract test ({{ file('tests/current/test_docs_contract.py') }}) also checks that every file, route and table the hand-written pages mention still exists, so the text cannot quietly point at something that has been renamed.

If you change the code and a hand-written page becomes wrong, fixing the page is part of the change. The pages live in templates/platform/docs/, one file each.

Who can read this

Only a signed-in platform admin who has been given access. The super admin always has it and grants or withdraws it for each other platform admin on the Team page (every change is recorded in the activity log). Anyone else, signed in or not, is turned away as if the page did not exist. The public marketing page is the only page here that needs no sign-in.

These pages describe how the platform is built, including how it is protected. Do not paste them into chats, tickets or slides outside the company.

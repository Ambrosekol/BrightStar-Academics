Add a page to the school's admin area

Example: a "Class notices" page for staff.

  1. Choose the permission. Reuse an existing one if it fits ({{ page('reference-permissions', 'the catalogue') }}); otherwise add one (next recipe).
  2. Write the route in the right package, for example {{ file('blueprints/school/routes.py') }} or a new module next to it: 
    @app.route('/admin/school/notices')
@admin_required
def admin_school_notices():
    rows = all_rows(select(Notice).order_by(Notice.id.desc()).limit(100))
    return render_template('school_notices.html', notices=rows)

@app.post('/admin/school/notices/new')
@admin_required
@csrf_protect
def admin_school_notice_new():
    ...
    db.session.commit()
    audit_log('school_notice_created', 'school', 'notice', notice.id, {})
    flash('Notice saved.', 'success')
    return redirect(url_for('admin_school_notices'))
  3. Map both endpoints to a permission in ADMIN_ENDPOINT_PERMISSIONS ({{ file('core/security.py') }}): 'admin_school_notices': 'school.notices.view', 'admin_school_notice_new': 'school.notices.create'.
  4. If it is a new module, import it at the bottom of {{ file('app.py') }} next to the others.
  5. Write the template extending admin_base.html. Put the CSRF token in every form: {% raw %}{% endraw %}. Read the school's name from school_brand, never from a string.
  6. Add the menu entry to the one list in {{ tpl('admin_base.html') }}, guarded by the same permission.
  7. Audit friendly text. Add a sentence for the action to the friendly dictionary in audit_log's helper in {{ file('core/security.py') }}.
  8. Prove it. Add a submission for the POST to tests/verification/write_paths_pg_posts.py and the route pattern to pg_posts_coverage.py (EXERCISED). Run the contract suite and that script.

Add a permission

  1. Add a tuple (key, label, group, description) to ADMIN_PERMISSION_DEFS in {{ file('core/security.py') }}. Keys are dotted: area.thing.action.
  2. Map the endpoints to it in ADMIN_ENDPOINT_PERMISSIONS.
  3. Decide which role presets get it (ADMIN_ROLE_PRESETS). Presets are seeded once: existing schools keep their edited roles, so a new permission appears in a preset only for new schools. The School Admin role always gets every permission at start.
  4. The catalogue is seeded into each school on start (init_admin_security), so no migration is needed.

Add a column to an existing table

  1. Add it to the model in models/, with a default or nullable: 
    note = db.Column(Text)                                   # nullable: fine
flag = db.Column(Integer, nullable=False, default=0, server_default=text('0'))
  2. On the next start every school's database gets the column (_add_missing_columns in {{ file('app.py') }}); or run python -m control_plane upgrade.
  3. Run python tests/current/run_current.py. The models match the database check compares against the first registered school and fails until you have upgraded it, which is the reminder to do so.

The platform registry works the same way: {{ file('control_plane/models.py') }}, upgraded by _add_missing_columns in {{ file('control_plane/registry.py') }} when the app starts. That is how docs_access was added.

Add a table

  1. Add a model class to the right module in models/ and export it from {{ file('models/__init__.py') }} (both the import and __all__).
  2. Give it a docstring: the Data model reference shows it.
  3. Restart or run upgrade; create_all() creates it in every school.

Add a per-school setting

For a simple value the school chooses (a text, a number, a switch): store it as a key/value row in school_settings ({{ table('school_settings') }}), as the report card head's name and the CA weights are ({{ file('blueprints/school/report_card_data.py') }}, report_settings and save_report_settings). Provide a default so an unset key means the default. Do not add a column to the school row for every setting.

Notify parents about something

  1. Write the sender in {{ file('core/notifications.py') }}, modelled on _notify_parents_report_card_ready: look the student up, add in-app SchoolNotification rows for linked parents, then best-effort email and WhatsApp to the guardian, each wrapped so one failure does not stop the other.
  2. Call it after the commit. If it may be slow or covers many students, register it with @job_handler('name') and call it through enqueue('name', **kwargs) ({{ file('core/jobs.py') }}) rather than calling it directly, so a restart mid-send is retried instead of lost; build any link with url_for(..., _external=True) inside the handler (it runs in a request-like context on the school's own address), and keep its keyword arguments to plain, JSON-serialisable values (ids, not ORM objects).
  3. In tests, set A.app.config['BACKGROUND_INLINE'] = True so the work runs immediately and the fake mail server can be inspected.

Add a page to the platform console

@app.route('/platform/thing')
@platform_host_only
@platform_required
def platform_thing(): ...

Order matters: platform_host_only first (so the route does not exist on a school's address), then platform_required. Add @superadmin_required for the super admin only and @csrf_protect on any POST. Extend platform/base.html. Record meaningful actions with audit(...) and give the action a label in ACTION_LABELS ({{ file('control_plane/team.py') }}).

Add or change a documentation page

  1. Create templates/platform/docs/<slug>.html starting with {% raw %}{% extends "platform/docs/_layout.html" %}{% endraw %} and the macro import line copied from any existing page.
  2. Register the slug, title and one-line summary in DOC_GROUPS ({{ file('control_plane/platform_pages.py') }}). Order there is the sidebar and the previous/next order.
  3. Refer to code with the macros, never bare text: {% raw %}{{ file('core/security.py') }}{% endraw %}, route('endpoint'), table('name'), perm('key'), tpl('name.html'). They make links, and the docs contract test fails if what they name does not exist.
  4. Put a sample containing {% raw %}{{{% endraw %} inside a raw block or Jinja will try to run it.

Create a school for testing

python -m control_plane create-tenant demo "Demo School" --admin-username demo_admin
python -m control_plane list

Then open http://demo.localhost:5000. Delete nothing by hand: a school is a database and a folder, and the registry knows about it. Use throwaway schools in the verification scripts; they clean up after themselves.

Debugging tips

  • A page shows "address not found" in development: you used localhost. Use platform.localhost or <code>.localhost.
  • A query fails only in a browser: run the same submission through write_paths_pg_posts.py; it reports the database error and the route.
  • A template renders wrongly for one school: check school_brand and that school's settings rows, not the template first.
  • "No school is selected for this request": you are querying a school table from a context where no school is chosen (a thread, a script). Wrap it in tenant_context(info) ({{ file('control_plane/context.py') }}).

Step 2 of 3

Import enrolment history

{% if can_import_history %}

For students who already exist here: one row per student per year, matched by admission number. A year that does not exist yet is created when it is an earlier year than the current session.

Required

{% for c in history_required %}{{ c }}{% endfor %}

Optional

{% for c in history_optional %}{{ c }}{% endfor %}
Rules for this file
  • enrolled_at and completed_at are dates in the format YYYY-MM-DD, for example 2023-09-11. Leave completed_at empty while the year is open.
  • level is one of: {{ history_levels|join(', ') }}.
  • outcome is one of {{ history_outcomes|join(', ') }}. A graduated row archives the student once that year is recorded. Their record stays on file.
  • session is matched by name, such as 2023/2024. An earlier year that does not exist is created inactive and never as the current session, and the import records who made it and why. The current session is never changed.
  • Up to {{ history_max_rows }} rows per file.

Step 3 of 3

Import past results

{% if can_import_results %}

One row per student, subject, term and session. A student has as many rows as they have subjects, terms and sessions. Imported results are released straight away and appear on academic records and report cards.

Required

{% for c in results_required %}{{ c }}{% endfor %}

Optional

{% for c in results_optional %}{{ c }}{% endfor %}
Rules for this file
  • Run steps 1 and 2 first. The session and the subject must already exist.
  • term is First Term, Second Term or Third Term.
  • Scores and maximums are numbers, and a score cannot be above its maximum. Leave the test columns empty when no test was recorded.
  • Graduates are matched too, so the results of students who have left are brought across.
  • A subject, term and session that already has a result for the student is left as it is and reported, never overwritten.
  • Up to {{ results_max_rows }} rows per file.

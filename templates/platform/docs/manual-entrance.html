The entrance examination lives in its own workspace: question banks (JSON files in the school's own storage), papers configured for the current session ({{ route('admin_entrance_config') }}), candidates ({{ route('admin_candidates') }}) who sit timed papers, and the admissions waitlist ({{ route('admin_candidate_admissions') }}). Timing and scoring happen on the server; each attempt keeps a frozen copy of its questions, so editing a bank never changes an exam already sat ({{ file('core/entrance.py') }}).

Papers and question banks

"This paper is not ready because its question bank is empty."

You see
A candidate cannot start a paper; the message above, or "This paper has an invalid examination configuration" / "is not linked to a verified examination configuration. Please contact the school administrator."
Why

The paper's bank has no questions, or the paper was never configured (made live) for the current session.

Fix
  1. For the standard set: Exam Configuration › Set up the standard entrance papers configures every paper in one click.
  2. For a school's own bank: import it (Question Banks › Import from file), then configure and make it live on Exam Configuration.
Check
The candidate's dashboard shows the paper with a Start button.

"This configuration cannot be activated because its question set is not valid for a 100-point examination."

You see
This configuration cannot be activated because its question set is not valid for a 100-point examination.
Why

A paper is always out of 100. The number of questions served must split 100 into whole hundredths (20, 25, 40, 50 …).

Fix

Choose a question count that divides 100 that way, or leave it blank for the default.

Check
The configuration activates.

"This entrance configuration is already assigned to a candidate paper…"

You see
A configuration cannot be edited because candidates already have it.
Why

Changing a paper under candidates who already have it would make their exams unfair or incomparable.

Fix

Create a new configuration for the changed set-up and activate it; existing candidates keep theirs.

Check
New candidates get the new paper.

"This question bank is locked by School Admin…"

You see
This question bank is locked by School Admin. Unlock it before editing questions. (or adding, deleting, reordering)
Why

A bank can be locked (usually during a live exam) so nothing changes mid-paper ({{ table('admin_resource_locks') }}).

Fix

The School Admin unlocks it from Settings › Controls & alerts ({{ route('admin_controls') }}) once the exam is over.

Check
Edits save.

Candidates sitting a paper

"You have already taken this paper." / "You must submit your current paper…"

You see
You have already taken this paper. Please contact the school administrator if another attempt is required. — or — You must submit your current paper before starting another paper.
Why

One attempt per paper, one paper at a time.

Fix

For a genuine second attempt (a power cut ruined the first), staff grant a retake on the candidate's page. "A retake can only be granted after the previous attempt is completed" means the first must be finished (or its time run out) first.

Check
The candidate can start the paper again.

The power went off, or the server restarted, during the exam

You see
Candidates' screens froze or went blank; the server or the light came back a few minutes later.
Why

Answers are saved on the server as they are given, and the exam page retries saving when the connection drops. Someone sitting a paper is never signed out by a restart or the sign-in time limits. The clock keeps running on the server, though: time lost to the cut is not given back automatically.

Fix
  1. Tell candidates to reload the page (or sign in again on another computer): they continue where they were, with their answers.
  2. A paper whose time ran out during the cut is finished from the answers already saved.
  3. If many lost a lot of time, grant those candidates a retake (above).
  4. Before a big entrance day, measure the server: python tests/verification/load_test_exam_answers.py --school CODE.
Check
Candidates' attempts show their saved answers; the results page shows their scores.

The result image cannot be made: "Google Chrome was not found…"

You see
Sharing or downloading a candidate's result image fails; the log says "Google Chrome was not found. Install it, or set BRIGHTSTARS_CHROME to its full path." (or "Chrome failed: …").
Why

The result image is drawn by a headless Chrome or Chromium on the server.

Fix
  1. Install it: sudo apt install chromium (or Google Chrome).
  2. If it is somewhere unusual, set BRIGHTSTARS_CHROME to its full path.
  3. "Chrome failed": run it by hand as the service user (chromium --headless=new --screenshot=/tmp/x.png about:blank) to see why; missing fonts or a sandbox restriction are common on minimal servers.
Check
The candidate's result image downloads.

Admissions

A candidate is not on the admissions waitlist

You see
A candidate who registered is missing from Admissions.
Why

Only candidates who have attempted at least one paper are listed. Seeing the waitlist needs {{ perm('candidates.admit') }}.

Fix

The candidate sits a paper first. Give the admissions officer's role the admit permission.

Check
The candidate appears, ranked by their overall percentage.

Admitting is refused

You see
"This candidate has already been admitted." · "An admitted candidate cannot be declined." · "… could not be admitted (…)."
Why

Admitting is final: it creates a real student, an enrolment and a login (and a parent account) ({{ file('blueprints/entrance/admissions.py') }}). The bracketed reason in the last message says what went wrong in plain words.

Fix

For "could not be admitted": the usual causes are no current session, a class missing for the entry level, or the school's numbering rules (see {{ page('manual-files', 'Files, uploads, storage and imports') }}). Fix it and admit again; nothing was half-created.

Check
The new student appears in their class, and on New students to bill.

The candidate's page shows the new student's login

You see
After the result is released, an admitted candidate's dashboard shows a Login ID and a one-time password.
Why

By design: so the family can sign in as the new student. The password is stored encrypted and disappears once the student changes it.

Fix

Nothing. If it was lost, staff reset the student's password from the student's page.

Check
The student signs in and chooses a password.
